# 0.3 运营路线与资源乘车需求

用户新增要求：扩大单格车站；持有资源也可乘车；殖民者偏好列车；建立运营路线；列车持续存在并自行运行，同一轨道仅一辆自动列车。

## 实现基线与修改意见

1. 新建 3×3 车站，中央三格东西向轨道、两侧候车区，保留免费施工。旧 LR_Station 单格定义保留兼容已有存档，隐藏旧式建筑的建造入口；用户可拆旧站换新站。不要直接扩大旧定义并覆盖存档周围建筑。
2. 先实现两端站往返服务 A↔B，无需驾驶员，无人也运行。列车是可选择、可存档的实际 Building 对象，车辆状态由地图服务推进，不因乘客到来生成或在下车时销毁。
3. 每个连通轨道网最多一条运营路线/一辆自动列车，包括全部分支。多个互不连接的路网可分别运营。合并路网时保留一条服务运营，其余列车暂停；保留对象以便调整路网。
4. 玩家通过车站按钮选择另一端站建立路线，可暂停/恢复、撤销路线。当前支持两个端站，不含中途停站、环线或换乘。
5. 四人列车，端站停靠 90 ticks、轨道每格 3 ticks。乘客步行到站，排队等待现有列车；空位不足则等待下一次停靠，按计划进入队列的先后顺序上车。
6. 默认偏好轨道：长途允许等待，并可接受至多约 50% 的估计时间增加；保留合理接驳和距离限制，避免短途或明显绕路。提供偏好开关，关闭后按速度收益选择。
7. 携带普通物品的 Pawn 可乘车。原 carryTracker、物品实例/数量、Job ID 和移动 Toil 保留，先覆盖 HaulToCell、HaulToContainer。搬运其他 Pawn 仍排除；不是无人货车或独立货物仓库。
8. 乘客依旧存在地图上，显示位置跟随列车。征召/取消工作、停运、断轨或站点失效时，释放乘客并恢复原目标寻路，携带资源不转移到别的容器。
9. 保存运营路线、列车引用、位置、方向与停靠计时。读档恢复列车运行；乘车/候车中的 Pawn 从当前位置恢复原工作，避免死锁或重复资源。兼容 0.2 的无服务行程记录。

## Use cases 与验收

| 场景 | 期望行为 | 验收 |
|---|---|---|
| 扩大车站 | 新站实际占地及绘制为 3×3，内含贯通轨道 | 定义、网格、原生免费施工和实际截图 |
| 建立路线 | 选 A 与连通的 B，只创建一辆持久列车 | 第二次/分支创建被拒绝，列车数量为一 |
| 无人乘坐 | 空车自行往返，在端站停靠 | 无乘客期间位置变化、反向及对象引用不变 |
| 持资源搬运 | 搬运工带钢材到站、乘车、到仓库卸货 | 同一钢材实例/数量、原 Job 保持并实际送达 |
| 持资源断轨 | 车停在最后有效格，乘客恢复原搬运 | 无资源丢失/复制，最终到达原交付点 |
| 多人等待 | 空位优先给早到的乘客，超出四人等下一班 | 十二人均乘车，单车容量不超过四人 |
| 偏好列车 | 稍慢的合理服务仍优先；短途仍步行 | 纯策略边界及真实长途任务 |
| 停运/征召 | 乘客立即释放，列车对象仍存在 | 原工作/携带物保留，暂停时位置不变 |
| 断轨修复 | 服务停止并显示原因，修复后自动继续 | 列车不复制、不瞬移到起站，状态恢复 |
| 路网合并 | 同连通网最多一辆自动运行 | 保留一个运营服务，另一列车暂停 |
| 存读档 | 列车引用和路线保留，Pawn 恢复原任务 | 新进程加载、无重复车/货物、继续运行 |

## 开发步骤

1. 增加服务状态与实际列车定义，按地图推进空载往返；维护轨道网络占用与拓扑变更。
2. 自动规划只使用已建立的服务；候车、容量、上下客与移动绑定到现有列车。
3. 扩展携物与搬运 Job、保留原任务生命周期，加入偏好策略与实际等待估算。
4. 新车站、线路建立/停运/撤销按钮、状态说明与中英文本。
5. 纯逻辑及实际引擎检查，覆盖资源交付、空载运营、单车、排队、中断和读档，更新安装包。
