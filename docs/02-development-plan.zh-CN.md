# 开发方案与资料依据

本页保留 0.1–0.3 的开发历史与当时的版本资料。0.4 已针对本机 `1.7.4977 rev1248` 重建，轨道改为八方向加权 Dijkstra，增加多站、货运和地图预览；当前规则与证据见 [07](07-train-system-requirements.zh-CN.md) 和 [08](08-train-system-validation.zh-CN.md)。

## 资料与环境结论

2026-10-12 的 [Ludeon 官方 1.7 / Waylith 公告](https://ludeon.com/blog/2026/10/announcing-the-waylith-engine-and-update-1-7/)确认：1.7 在 Steam unstable，绝大部分既有 Mod 继续兼容，支持新的 C# 特性。公告没有给出独立轨道/车辆 API 或完整 Waylith SDK。

2026-10-13 本机 `Version.txt` 为 **1.7.4977 rev926**；`RimWorld.runtimeconfig.json` 的 TFM 为 `net10.0`，使用 `10.0.10-waylithclr.dev`；安装根目录存在 `Assembly-CSharp.dll`、`UnityStubs.dll`、`Waylith.dll`。本机 Harmony Workshop 已含 `1.7/Assemblies/0Harmony.dll`，About 版本为 3.0.0.0。本地 `ModUpdating.txt` 提供官方 Mod 文件结构、About 和 LoadFolders 约定。

实现以本机程序集反编译/接口检查为准，不将 Unity 时代教程当成 1.7 API 证明。本次没有找到可独立核实的公开 1.7 Modder Primer 全文，后续获取后应补充差异。无需安装 Unity 编辑器；本项目使用 Verse/RimWorld 游戏接口及少量兼容绘图接口，避免原生 Vulkan、Shader、AssetBundle 和引擎线程中的地图修改。

## 技术选择

路网使用地图组件持有轨道与车站格子索引，建造/拆除时标记重建。上下左右连接的图用 BFS 求最短轨道路径。无需修改原版多线程 A*。

自动交通在 Pawn 寻路入口/推进中寻找低成本接驳方案。维持原 Job 与目的地，乘车期间接管移动阶段，到站再恢复原寻路。实现前检查实际 `Pawn_PathFollower` 的到达、失败、停止和序列化行为，防止接驳到站误触原工作完成回调。

比较 `步行到站 + 上下车 + 轨道耗时 + 下车后步行` 与直接走路。已实现两端 24 格有限范围四向 Dijkstra 的接驳估算，原步行成本根据原版已计算路径的剩余节点估算，并过滤障碍、允许区域和已知危险；下一阶段加入拥堵和更多第三方成本修正，并缓存规划结果。

轨道/车站用 XML ThingDef。小车通过现有绘制接口画在实际乘客下方，乘客不离开地图。0.1 复用原版贴图；用户后续明确要求生成占位美术，因此 0.2 使用三张原创生成 PNG，并将静态连接轨道烘入地图网格。

## 逐步里程碑

| 阶段 | 工作与产物 | 通过门槛 |
|---|---|---|
| M0 需求与接口 | 明确自动长途场景、范围、风险；固定实际程序集版本与 Harmony | 用户关键方向已确认，API 不凭猜测 |
| M1 可加载骨架 | About、Defs、语言、.NET 10 构建脚本、只读游戏引用 | 编译通过，游戏无 Def/类型加载错误 |
| M2 路网 | 轨道/站点索引、分支 BFS、断连处理、接驳收益算法 | 独立逻辑测试覆盖直线/转角/分支/断轨/收益 |
| M3 自动 POC | 寻路拦截、接驳→上车→沿轨道移动→下车→继续原工作，小车可见 | 长途自动乘车、短途步行、原 Job 完成 |
| M4 生命周期 | 拆轨/拆站、征召/倒地/换工作、读档恢复、地图清理 | 无丢 Pawn、无复制、无卡死；游戏内测试记录 |
| M5 产品化 | 实际路径耗时、缓存、队列/运力、电力和研究、运货、设置和兼容 | 多 Pawn 性能与兼容测试、平衡与 UI 验证 |

当前 M1–M3 已完成机制验证；M4 的断轨、征召、乘车中保存与重启读档已经通过真实引擎测试。0.2 推进 M5 的部分产品化：免费施工定义、站名、原生直线铺轨、索引/缓存/预算、提前停止接驳搜索、平滑显示及生成占位素材。队列/运力和更多兼容仍待开发；材料、电力按新的要求保持免费。新引擎不自动解决 Job 语义、调度和乘客状态问题。

## 人工参与

- 当前游戏已更新到 1.7，不需手动切分支。
- Mod 本体与 Harmony 可在游戏的 Mod 菜单启用；使用临时配置/测试存档完成验收。
- 若图形交互工具不可用，需用户进行一次游戏内检查并提供日志或现象；开发端继续负责构建、修复和打包。
- 公开发布与 Steam Workshop 上传留到实机验收后。


## 0.3 运营服务实施

当前实现推进 M5 的队列、运力和携物任务：新建 3×3 车站，建立两端往返服务，使用真实 Building_RailTrain 对象；服务独立推进，序列化列车引用、路径、方向和停靠状态。连通网只在拓扑变更时重建，服务占用整个网络。合并后多余服务停运，分离后恢复。

乘客规划复用服务固定路径，不再为每名乘客创建轨道路径或绘制临时车辆。到站排队，四座容量，先到先上车。携带物品保留在原 carryTracker，接入 HaulToCell / HaulToContainer；原 Job 与 Toil 不替换。偏好策略加入当前列车方向及停靠计时的等待估算。读档保留实际列车，释放运输中的 Pawn 继续原任务。

详细 use cases、修改意见与实施顺序见 05-service-requirements.zh-CN.md；最终引擎证据见 06-service-validation.zh-CN.md。材料、电力、燃料与研究继续保持免费。中途停站、环线、换乘与独立货运尚未实现。
