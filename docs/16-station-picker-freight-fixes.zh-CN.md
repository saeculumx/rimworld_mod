# 0.8：站台选择与货运一致性

## 用例与验收

1. 玩家添加、替换路线停站时，可以平移和缩放当前地图。编辑器切换为侧栏，所有候选车站、具体站台都有编号；列表支持定位，地图支持直接点击轨道行选择站台。未连通或重复的站台显示原因，不能误选。取消选择保留路线草稿。
2. 工业区只需一个装卸站台时，可以建造免费 3×3 单站台货运仓库。单／双／四站台仓库分别占 3×3、5×5、5×9；放置预览、蓝图、建成布局使用相同储存行与轨道行。
3. 仓库默认接受所有原版可储存物品，包括尸体；原版存储过滤器与实际接收规则必须一致。保留用户已有过滤器。物品活体不进入货运容器。不存在无限建筑容量：储存格每格三堆，轨道行不储物。
4. 每列车固定 12 个货运格，每格一个原版堆栈。客货两用列车另有四个座位。装载、自动停站和容量显示共同使用一个常量；旧存档中真实货物不丢失。
5. 货运仓库与客运站可组成路线。仓库接收进入存储格，客站卸到站外安全地面；卸不下时保持真实货物，继续行驶，发不暂停的 info 消息。
6. 三格双轨门在关闭时两片门叶完整封住宽度，不出现中心透明裂缝；完全打开时让出两条轨道与中间通道。不同旋转方向一致，沿用原版气密、材质耐久和速度。

## 日志根因

用户提供日志的主要报错是尸体 HaulToCell 在同一 tick 被重复启动。原默认存储过滤器允许尸体，但 Building_RailWarehouse.Accepts 硬编码拒绝尸体，导致原版搬运工作选择了永远无法完成的目的地。修复过滤器和接收一致性，并通过真实原版搬运工作与客货站间实际运输验证。

## 验证范围

运行本地 1.7.4977 / Waylith 引擎的隔离测试，不修改玩家存档。新增尸体搬运、仓库／客站往返卸货、12 格容量、单站台及预览布局、地图站台选择和闭合门截图；回归仓库多站卸货、拒收／部分卸货及存档读取。
